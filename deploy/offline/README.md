# TRE Offline Deployment

This directory contains Docker Compose configuration for running Azure TRE locally in offline mode with Azure Cosmos DB Free Tier and Azurite storage emulator.

## Phase 1 Status

**Current Implementation:** Azure Cosmos DB Free Tier + Azurite  
**Reason:** Cosmos DB Linux Emulator is non-functional on macOS with Docker Desktop  
**Documentation:** See [docs/phase1-cosmos-emulator-workarounds.md](../../docs/phase1-cosmos-emulator-workarounds.md)

## Services

### Azure Cosmos DB Free Tier (Cloud Service)
- **Endpoint:** `https://tre-poc-cosmos.documents.azure.com:443/`
- **Database:** AzureTRE
- **Containers:** 6 (Resources, ResourceTemplates, ResourceHistory, Operations, Requests, Migrations)
- **Throughput:** 400 RU/s per container (2400 RU/s total)
- **Cost:** ~$0.05/day (exceeds 1000 RU/s free tier allowance)
- **Setup:** Automated via `scripts/setup_azure_simple.py`

### Azurite (Storage Emulator)
- **Image:** `mcr.microsoft.com/azure-storage/azurite:latest`
- **Ports:** 10000 (Blob), 10001 (Queue), 10002 (Table)
- **Connection String:** Uses default development storage account
- **Data Persistence:** Enabled via volume mount

### TRE API
- **Build:** From `../../api_app/Dockerfile`
- **Port:** 8000
- **Mode:** `DEPLOYMENT_MODE=offline`
- **Dependencies:** Waits for Azurite to be healthy (Cosmos DB is cloud service)

## Prerequisites

1. **Azure Cosmos DB Free Tier Setup**
   ```bash
   # Install Azure SDK dependencies
   pip3 install -r scripts/requirements.txt
   
   # Run automated setup (creates resource group, Cosmos DB, containers, .env file)
   python3 scripts/setup_azure_simple.py
   ```
   
   This creates:
   - Resource group: `tre-poc-rg`
   - Cosmos DB account: `tre-poc-cosmos`
   - Database: `AzureTRE`
   - 6 containers with 400 RU/s each
   - `.env` file with connection details

2. **Docker Desktop**
   - Ensure Docker Desktop is installed and running

## Quick Start

```bash
# From project root
cd deploy/offline

# Start all services
docker-compose up -d

# Check service health
docker-compose ps

# View logs
docker-compose logs -f tre-api

# Test API
curl http://localhost:8000/api/health
open http://localhost:8000/api/docs

# Stop all services
docker-compose down

# Stop and remove volumes (clean slate)
docker-compose down -v
```

## Healthchecks

Services have healthchecks configured:
- **Azurite:** Checks port 10000 availability
- **TRE API:** Polls `/api/health` endpoint
- **Cosmos DB:** Cloud service (no Docker healthcheck needed)

## Environment Variables

The `.env` file is automatically generated by `scripts/setup_azure_simple.py`.

Key variables:
- `DEPLOYMENT_MODE=offline` - Enables offline mode (no Service Bus, no Azure AD auth)
- `STATE_STORE_ENDPOINT=https://tre-poc-cosmos.documents.azure.com:443/` - Azure Cosmos DB endpoint
- `STATE_STORE_KEY=...` - Azure Cosmos DB primary key
- `AZURE_STORAGE_CONNECTION_STRING=...` - Azurite connection string

See `.env.sample` for full configuration template.

## Volumes

Persistent data is stored in:
- **Azure Cosmos DB:** Cloud service (data persisted in Azure)
- **Azurite:** Local volume `tre-azurite-data` for blob/queue/table data

## Network

All services are on the `tre-local` bridge network for inter-service communication.

## Troubleshooting

### API cannot connect to Azure Cosmos DB
- Verify `.env` file exists with correct `STATE_STORE_ENDPOINT` and `STATE_STORE_KEY`
- Check Azure Portal that Cosmos DB account is running
- Ensure containers exist: Resources, ResourceTemplates, ResourceHistory, Operations, Requests, Migrations
- Re-run setup if needed: `python3 scripts/setup_azure_simple.py`

### Azurite connection errors
- Ensure connection string uses `http://` not `https://`
- Check ports 10000-10002 are not in use on host
- Run: `docker-compose logs azurite`

### Authentication errors
- This is expected in offline mode
- Service Bus and Azure AD authentication are disabled
- Health endpoint shows Service Bus as "Not OK" - this is normal

## Cleanup

To remove Azure resources and local environment:

```bash
# Remove both Azure and local resources (default)
./scripts/cleanup_phase1.sh

# Only delete Azure resources (keep Docker containers)
./scripts/cleanup_phase1.sh --azure-only

# Only clean up Docker (keep Azure resources)
./scripts/cleanup_phase1.sh --local-only
```

**Cost Impact:** Deleting Azure resources stops ~$0.05/day charges.
